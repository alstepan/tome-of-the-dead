### Banks & tape

| Bank | Contents | Size | Written by |
|------|----------|------|------------|
| 1 | sprite **sources** at *virtual* `$8000..` (MMU slot 2 = page 1): `ZX0_SOURCES=1` (default) = `build/zx0/sprites_zx0.asm` (see "Sprite sources (ZX0)" below); `=0` = the raw `assets/gfx/sprites/index.asm` (A/B only) | ZX0: `SRC_TOTAL` **7,219 B** (`$C000..$DC32` in bank 1), **9,165 B free**; raw: 16,384 B (full) | tape block 3 / .sna |
| 3 | sprite sources tail, virtual `$C000..` (MMU slot 3 = page 3) — **empty** with ZX0 (raw: 515 B), then the **bank-3 cold code** (`bank3_code..bank3_end`, below) | ZX0: 0 B sources + 960 B code = `BANK3_LEN` 960 B, **7,232 B free** to `AY_RESERVE $E000` (raw: 515 + 960 = 1,475, 6,717 free). ASSERT `bank3_end <= AY_RESERVE`; `$E000-$FFFF` = A8 AY reserve | tape block 4 / .sna |
| 0, 4, 6 | **pre-shift pool**: every frame variant (facing × shift), boot-generated by a bump allocator (no variant straddles a bank) | need 38,176 of 49,152 B (monsters 22,688 + largest hero 12,608 + 2 select idles + straddle slack; ASSERTed) | `gen_kind` / `gen_frame` at boot and at hero select |
| 7 | **clean-background shadow** (R-1 erase lever): the room's tiles in screen layout, bitmap within `$C000..$D79F` (char rows 0–20 only), attrs `$D800..$DA9F` | 6048 B used | `shadow_rect` / `shadow_room` on room entry + potion pickup |

Sources are read only at generation time via `copy_virt` (virtual < `$C000` →
bank 1 at +`$4000`, else bank 3; a frame straddling `$C000` is split) — with
ZX0 only the 4-B frame descriptors and the raw items/tiles go through
`copy_virt`; the packed blocks are read by `dzx0_standard` straight from the
`$C000` window (a block never straddles virtual `$C000`: the tool pads it into
bank 3, ASSERTed). The pool
and shadow banks are uncontended (0/4/6) resp. contended (7, erase-only).
`PORT_7FFD_SHADOW` always has bit 4 = 1 (48K ROM: IM1 ISR, charset, LD-BYTES).

Tape: BASIC `10 CLEAR VAL "24575": LOAD "" CODE: RANDOMIZE USR VAL "<start>"`
(the 5 USR digits are emitted from the `start` label, today `31325` = `$7A5D`).
ONE CODE block `lowram_code..code_end` (`TAPE_CODE_LEN`: bank-5 low-RAM cold
code `$7A5D..$7FFF` straight into the bank-2 image `$8000..code_end`; the
low-RAM block is ORGed to end exactly at `$8000` so there is no gap), then two
**headerless** blocks (flag `$FF`) that `start` loads with ROM `LD-BYTES`
before falling into `boot`: bank 1 (`SRC_LEN_LO`) and bank 3 from `$C000`
(`BANK3_LEN` = source tail + bank-3 cold code). The `.sna` enters at `boot`
(all banks preloaded). `tests/game.py` #50 checks bank 1, bank 3 (whole
`BANK3_LEN`) and the low-RAM cold block byte-equal to the `.sna` after a real
tape load.

### Sprite sources (ZX0, A5)

Generated before every build by `tools/zx0_sources.py` →
`build/zx0/sprites_zx0.asm` (gitignored, deterministic; needs `tools/bin/zx0`
from `tools/setup_zx0.sh`, else it stops with that hint). Layout, in order, at
virtual `$8000` (`sprite_src`):

| Part | Contents | Size (measured) |
|------|----------|-----------------|
| raw items + tiles | `item_*`, `tiles_*` `.asm` INCLUDEd verbatim (init_tiles reads them with `copy_virt`; never the generator) | 265 B |
| packed blocks `zblk_0..zblk_22` | per kind, in `data.asm` FRM (= fid = `gen_kind`) order, 1–4 consecutive frames of ONE kind, raw ≤ `GEN_SCRATCH_LEN` 1,536 B; each one ZX0 v2 standard forward stream. Partition per kind = fewest packed bytes (DP over 1..4-frame splits) | 68 frames, raw 16,048 → **6,682 B (2.40×)** |
| frame descriptors (4 B each) | the frame's label `nm` (= `FT_SRC` in `frame_tab`): `DW zblk_N` (virtual block addr), `DW GEN_SCRATCH + raw offset`; plus `nm_w/h/cols/ax/ay` EQUs and `nm_len` = raw pixel bytes (cols·H·2, no ATTR byte) | 68 × 4 = 272 B |

Build-time metadata per block (EQUs, in the `.sym`): `zblk_N_raw`,
`zblk_N_packed`, `zblk_N_first`, `zblk_N_n`; totals `ZX0_BLOCKS`, `ZX0_FRAMES`,
`ZX0_PACKED_RAW`, `ZX0_PACKED_TOTAL`, `ZX0_RAW_SRC_TOTAL` (16,899 = what the
raw build assembles; the per-kind `index.asm` tables `<kind>_frames/_meta/
_flags`, unread by the engine, are not emitted). Total 7,219 vs 16,899 B:
**freed 9,680 B** (bank 1: 9,165; bank 3: 515).

Generator path (`lowram.asm`): `gen_frame` → `zx0_frame` copies the
descriptor (`copy_virt`, 4 B) to `GEN_ZDESC`; if its block ≠ `GEN_ZBLK` it
pages the block's bank and `dzx0_standard` unpacks it to `GEN_SCRATCH`
(`$6000`); the frame is then read in place (`GEN_BASE` = scratch address; no
copy to `GEN_SRC`; `mirror_src` reads `(GEN_BASE)`). `GEN_ZBLK` = one-block
cache, cleared by `gen_kind` (the scratch may hold room maps since the last
session), so each block is unpacked once per `gen_kind`. `GEN_SRC` stays for
`init_tiles` (raw items). Decompressor = `src/dzx0_standard.asm` (vendored,
pinned commit, unmodified, 68 B); `zx0_frame` + `dzx0` = 121 B
(`zx0_code..zx0_code_end`, ASSERT ≤ `ZX0_BUDGET` 128).

### Cold code placement (A3) and far calls

Hot (per-tick) code stays in bank 2 (uncontended). Cold code lives in two
contended places, chosen by whether it pages `$C000`:

| Where | Why | What |
|-------|-----|------|
| bank 5 low RAM `lowram_code..$7FFF` (`src/lowram.asm`) | always mapped: may page any bank through `$C000` | `start`, `boot`, `check_paging`, `start_game`, `init_kbd_mirror`, `sel_tab`, the generator (`pool_banks`, `alloc*`, `build_bitrev`, `copy_virt`, `gen_kind/frame/facing/variant`, `mirror_src`, `mul8`, `frt_ptr`, `sel_frt_copy`), `init_tiles` + its stand-in glyphs / `tile_attr_src` / `tile_src_tab` / `bg_tiles` |
| bank 3 after the source tail, `bank3_code..bank3_end` (`src/bank3.asm`) | needs no other `$C000` bank while running | hero select (`sel_run`, `select_loop`, `select_tick`, `row_attr_fill`, select strings); transition scrolls (`hscroll_room`, `vscroll_room` and their row/column movers) — they touch only the `$4000` screen, `ROOM_MAP`/`NEXT_MAP`/`TILE_*` (bank 5) and `TMP4/5` (bank 2) |

Bank-3 code is entered only via `far3` (bank 2, `gfx.asm`): HL = target, A =
argument; saves `PORT_7FFD_SHADOW`, pages bank 3 (`page_bank`: bit 4 = 1,
shadow before `OUT`), calls, then `restore_page` writes the saved value back
(shadow first, then `OUT`); BC/DE/HL/IX of the target pass through. Bank-3
code must never page `$C000` itself; the select screen blits through
`blit_keep` (bank 2), which re-pages the caller's bank after the pool blit.
`enter_select` (bank 2) = `far3 sel_run` → `jp start_game` (bank 5). After
the A7 double buffer the scrolls must keep operating on the `$4000` screen
(display bank 5 during the transition, then present to 7) — if A7 wants them
to scroll bank 7 at `$C000` instead, they move to bank 5 low RAM (+759 B,
which the reserves below do not leave room for).

Fit (ASSERTed: `lowram_code − ZX0_RESERVE − FDESC_RESERVE ≥ LOWRAM_FREE_END`):
3,104 fixed buffers + 288 A6 tiles + 1,920 descriptors + 1,572 cold code (incl.
the 121 B ZX0 code) = 6,884 of 8,192 B → 1,308 spare (`LOWRAM_SPARE`), enough for ~0.6 KB of level state with
~0.7 KB margin. A separate 1.5 KB ZX0 scratch would NOT fit in addition — hence
the alias. `$5B00-$5BFF` and `$5CC0-$5FFF` (~1,088 B, E: free once `boot` has
moved SP off the BASIC stack; the 48K ROM ISR only uses `$5C00-$5CBF`) are a
further runtime-only (not tape-loadable) reserve.

### Test probe labels

`tick_work` (tick work starts), `wait_tick` (tick work done, render complete) and
`select_tick` (after the select-screen HALT; bank 3 `$C2xx` — only bank-3 code
ever executes at `$C000+`, so a PC breakpoint there is unambiguous) exist so the
tests can stop the emulator at tick boundaries (ZEsarUX cpu-step + breakpoints).
`start.lo` (tape entry past the paging check) and `check_paging.locked`
(paging-lock stop) are probes for `tests/game.py` #43 (bank 5 low RAM).
`hscroll_room.step` (bank 3) is #29's mid-transition probe.

Per-game vs since-boot observables: `new_game` resets `TICK_COUNTER`,
`ANIM_TRACE`/`_IDX`, `BLIT_MISS`, `DMG_OVERFLOW`, `CLIP_TRAP` (plus RNG/turns);
`OVERRUN_COUNT`, `GEN_OVERFLOW` and `GEN_TRAP` count since boot. Moving them is
free; removing them breaks `tests/game.py` / `tests/budget.py`.
