# src/strings.txt — every game message (B3B-13). THE single source:
# tools/textpack.py (tools/build.sh step) packs it into dictionary-token
# streams (build/text/strings.asm, bank-1 text block; ids / lengths in
# build/text/strings_ids.inc) and round-trips the emitted bytes at build time.
#
# Format: one string per line, `name "TEXT"`; the id is TX_<NAME> (upper),
# its decoded length TXL_<NAME>. '#' starts a comment line. Text: ASCII
# 32..126, upper case, no '"'; every string is ONE line (game.md §3.4). Style:
# present tense, no trailing full stop. Order = id order (ids are stable only
# within one build: code uses the TX_* names, never numbers). The first 24
# strings keep their order (TX_NM_KNIGHT + kind arithmetic); new ones append.
#
# Length limits (tools/textpack.py style check, fails the build; the same limit
# is ASSERTed in strings_ids.inc): 32 chars (LOG_MAX) for every string except
# the 6x8-font lines named info_* and ft_* (info line / footers: 42 chars).
# info_* are pre-padded to the info-line fields (game.md §3.4): name = chars
# 0-15, numbers = 16-27, notes = 28-41; the tool checks that each non-empty
# field starts exactly on its boundary and that there is no trailing space.
#
# Long static text (help pages, book/scroll descriptions later) uses a
# block form instead, ZX0-packed per block (tools/textpack.py docstring):
#   @long NAME
#   UPPER CASE LINE, <= 42 chars, one per row of the page
#   @end
#
# Composed lines (show_impact_msg, lowram.asm): pre + kind name + post, so
# the pieces keep their spaces. The longest composition is ASSERTed against
# LOG_MAX in lowram.asm.
